PayPal Invoice Copilot

Demo script

An optional live walkthrough of about 2½ minutes on the zero-key demo route (rule-based demo agent and in-memory mock store), with what to say about each mocked part. It is separate from the published demo video.

Goal & audience

Show hackathon judges that one plain-English sentence becomes a structured invoice draft, and that send, remind and cancel wait for a click on the confirmation card. Target length about 2:30, presented live on the zero-key route (rule-based demo agent and in-memory mock store). The confirmation guarantee holds for that route; it is not a guarantee for the LLM route (see Security).

Two different things. The published demo video below (about 1:53) is a recording of a live run: Groq tool calling, a real PayPal sandbox draft, a confirmed send and a sandbox payment link. The script on this page is a separate live walkthrough without keys; it is not a transcript of that video.

Source: docs/media/devpost-demo.srt, src/lib/demo-agent.ts, src/lib/paypal-tools.ts

Prerequisites

  • A laptop with Node.js, npm and bash (Setup → Prerequisites), and the repo installed with npm install before the demo starts.
  • No accounts and no keys. Do not use someone else's PayPal or LLM account for the live variant.
  • A browser window at least 1280 px wide, so the chat and the invoice desk sit side by side.
  • Off screen: .env.local, terminals that print environment variables, password managers and private tabs.

Setup commands

cd paypal-invoice-copilot
DEMO_MODE=true FORCE_DEMO_AGENT=true npm run dev     # open http://localhost:3000

Both flags keep the run offline even if a .env.local with keys exists: DEMO_MODE=true turns off the PayPal and LLM checks in src/lib/config.ts, and FORCE_DEMO_AGENT=true selects the demo agent in src/app/api/chat/route.ts. Without any keys, plain npm run dev does the same.

Ready when the header badges read "Demo mode", "PayPal: local mock (no PayPal calls)" and "LLM: built-in demo agent", and the desk shows two seeded invoices: INV-1001 Acme Corp SENT USD 850.00 and INV-1000 Northwind Labs PAID USD 1200.00. Restarting the server resets to this state.

Script

Each step: what to do, what to say, what the screen shows. The diagram walks through the steps on its own.

  1. 0:00 The problem — show the welcome message, the desk and the "Demo mode" badge. Say: "Freelancers bill clients from chat notes. Invoice Copilot turns the note into an invoice. This run uses the built-in demo agent and a local store, so it needs no keys."
  2. 0:20 Create — type Invoice Acme Corp $500 for logo design, due in 14 days. The reply reads "Draft created in the local mock desk (no PayPal call)" with INV-1011 on a fresh start, and a "Human confirmation required" card whose summary ends "local mock desk, no email sent". Say: "It pulled out client, amount, service and due date, and created a draft. Nothing is sent yet."
  3. 0:50 Confirm the send — click Confirm. The desk shows the invoice as SENT and the unpaid total grows. Say: "Sending waits for my click. In this mode 'sent' is a status change in the local store, not a PayPal email."
  4. 1:10 Who owes what — type Who owes me money?. The reply lists unpaid invoices, totals and drafts from the desk.
  5. 1:30 QR — type Show QR for INV-1001. Say: "This QR is labelled PLACEHOLDER; a scannable PayPal QR is not wired up yet."
  6. 1:45 Remind — type Remind Acme about their invoice, then Confirm. The reply shows the reminder count. Say: "Remind uses the same confirmation card."
  7. 2:05 Cancel, safely — type Cancel invoice INV-1011, show the card, then press Cancel on the card. Nothing changes on the desk.
  8. 2:20 Close — end on the desk totals. Say: "With an LLM key and PayPal sandbox keys, create and list go through the official PayPal Agent Toolkit and confirmed actions call PayPal; that is the run in our video. Known gaps are in the Security doc."

Fallbacks

  • Something looks wrong, or a confirm fails → stop and restart the dev server; the in-memory store reseeds.
  • "I didn't catch that." → use the suggestion chips; the demo agent only knows fixed phrasings.
  • Invoice number differs from INV-1011 (the server was not fresh) → read the number from the reply and use it in the cancel step.
  • Server does not start → check Setup → Troubleshooting; if it cannot be fixed in a minute, switch to the video.
  • No working machine → play the published video above and say it is the recorded live sandbox run, not this walkthrough.

Cleanup

  • Stop the dev server you started (Ctrl+C in its terminal). All demo invoices and pending actions live in memory and disappear with it; there is nothing else to reset.
  • Close the app tab. No files are downloaded or written by the demo.
