PayPal Invoice Copilot

API

Four internal JSON routes used by the web UI, plus the tool set the agent can call. There is no published, versioned public API.

Interface type

HTTP JSON routes from the Next.js App Router (src/app/api/*/route.ts, Node.js runtime). They are internal to the app: there is no OpenAPI schema, no versioning, and no user authentication. POSTs must be same-origin application/json. While PayPal or LLM credentials are active, every route accepts loopback requests only (see Security). The second surface is the agent tool set the LLM can call, defined in src/lib/paypal-tools.ts.

Agent tools (names exposed to the LLM, from buildMockInvoiceTools): create_invoice, list_invoices, get_invoice, send_invoice*, send_invoice_reminder*, cancel_sent_invoice*, generate_invoice_qr_code (placeholder image, not scannable), summarize_outstanding. * = only creates a pending action (needs_confirmation). There is no confirm or execute tool. With the PayPal sandbox active, create_invoice and list_invoices run on PayPal sandbox, and the send / remind / cancel tools execute on PayPal after a UI confirm.

POST /api/chat

// request
{ "messages": [ { "role": "user", "content": "Invoice Acme Corp $500 for logo design, due in 14 days" } ] }

// rules: roles "user" | "assistant" only, string content ≤ 4000 chars, ≤ 40 messages,
// last message must be "user", no extra fields (system/tool roles → 400)

// response, demo agent (Content-Type: application/json, X-Invoice-Copilot-Mode: demo-agent,
// Set-Cookie: ic_sid=…; Path=/api; HttpOnly; SameSite=Strict on first call)
{ "type": "demo", "source": "local-mock",
  "text": "Draft created in the **local mock desk** (no PayPal call): …",
  "pendingAction": { "id": "pending-<uuid>", "tool": "send_invoice", "invoice_id": "INV2-DEMO-…",
                     "summary": "Mark INV-1011 (USD 500.00) as sent to … — local mock desk, no email sent",
                     "args": {}, "created_at": "…" },
  "mode": { "demoMode": true, "paypalConfigured": false, "llmConfigured": false,
            "paypalEnvironment": "mock", "llmProvider": "demo-agent" } }

// response, LLM path
{ "type": "llm", "source": "paypal-sandbox" | "local-mock", "text": "…",
  "toolCalls": [ … ], "toolResults": [ … ], "pendingAction": { … } | null, "mode": { … } }

The streaming (text/event-stream) variant was removed. The bundled UI never used it.

POST /api/confirm

// request
{ "pending_action_id": "pending-…", "confirmed": true }

// request header: Cookie: ic_sid=… (the session that received the proposal)

// 200 responses
{ "status": "sent" | "reminded" | "cancelled", "source": "local-mock", "invoice": { …Invoice } }
{ "status": "sent" | "reminded" | "cancelled", "source": "paypal-sandbox", "paypal_live": true,
  "tool": "…", "invoice": …, "paypal_status": "SENT", "href": "…" }
{ "status": "cancelled_by_user" }                                   // confirmed: false

// error responses
{ "status": "error", "code": "…", "error": "…", "retryable"?: boolean, "previous_result"?: { … } }

Lifecycle: pending → executing → succeeded | failed | outcome_unknown, or cancelled. Each action is dispatched to PayPal at most once per process and expires after 15 minutes. retryable: true appears only when nothing was sent (PayPal unavailable before dispatch; at most 3 attempts). An outcome_unknown error carries reconcile: true: check PayPal before proposing again.

GET /api/invoices?status=&page=&page_size=

{ "source": "local-mock" | "paypal-sandbox", "total": 2, "items": [ …Invoice (each with "source") ],
  "summary": { "unpaid_count": 1, "unpaid_total": "850.00", "paid_total": "1200.00",
               "draft_count": 0, "currencies": ["USD"], "by_recipient": [ … ] } }

The example values are the two seeded mock invoices (mock-store.ts:seed): INV-1001 SENT USD 850.00 and INV-1000 PAID USD 1200.00. status filters by exact status. page is clamped to 1–1000 and page_size to 1–100 (default 50). For PayPal rows the summary is computed from the returned page.

Try it

Against a local zero-key run (npm run dev; the README gives http://localhost:3000). No secrets are needed:

curl -s http://localhost:3000/api/health

# -c / -b keep the ic_sid session cookie: confirm must come from the same session
curl -s -c /tmp/ic.jar -X POST http://localhost:3000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"Invoice Acme Corp $500 for logo design, due in 14 days"}]}'

# copy pendingAction.id from the reply, then:
curl -s -b /tmp/ic.jar -X POST http://localhost:3000/api/confirm \
  -H 'Content-Type: application/json' \
  -d '{"pending_action_id":"<PENDING_ACTION_ID>","confirmed":true}'

curl -s 'http://localhost:3000/api/invoices?status=SENT'

These commands were not run while writing this page. In zero-key mode everything stays in server memory and nothing reaches PayPal.
